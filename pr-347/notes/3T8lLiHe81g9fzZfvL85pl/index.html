Calendar events

Calendar events

Use events for something happening over a date range or time interval. Use Tasks for work with a completion state, scheduled day, or deadline. Creating an event does not convert an existing note or task.

Back to Web workspace and track.

Register and edit

In the live Calendar, choose Month, Today, Tomorrow, or This week, then New event in the Events section. A day page also offers New event for that date. The selected vault determines where the event is saved; related-note choices come from that same vault.

In Today, Tomorrow, This week, and a day page, Show: All / Events / Tasks controls which agenda sections are visible. Choose Events to focus on appointments, Tasks for dated work, or All for both. The check mark and pressed state identify the choice; Tab and Enter or Space operate the buttons. On macOS, use Option-Tab when keyboard navigation skips buttons. The choice stays while moving dates or periods in that Calendar screen; opening another screen or reloading starts with All. Switching the filter does not save or delete anything. Day pages continue to show activity notes and the Journal action. Published calendars keep their read-only task snapshot and do not offer the live event filter.

Month cells list events on every day they overlap. A date with events opens its day agenda, including when a journal exists; the day's Journal action still opens that journal separately.

Enter a title and dates. All day uses a first day and a Last day, both inclusive in the form. For a three-day event from October 28 through October 30, enter those two dates. Without All day, enter start/end dates, times, and an IANA time zone such as Asia/Tokyo, America/New_York, or Europe/London. Standard IANA aliases such as US/Eastern are also accepted. Host-only names such as localtime, posixrules, and the Factory placeholder are refused. If this browser does not recognize a zone, choose a supported zone before changing an event's dates or times. Existing timestamps remain visible with their saved offsets, so an unsupported zone does not break the calendar.

Location, description, a source URL, and a related note are optional. Source URLs must use HTTP or HTTPS. Use Cancelled to retain a cancelled event visibly; a cancelled event is different from a completed task. Event rows open their editor, while Related note and Source open their references.

Save waits for confirmation. Failed input stays in the editor, and repeated clicks do not create another event. If confirmation times out, a save may already have completed: retry without changing the input to check the same operation safely. After an editing conflict, keep a copy of any draft text you need, then close and reopen the event to read the latest revision. Cancel or Escape leaves saved data unchanged and returns focus to the invoking control. An in-flight save must finish or time out before the editor can close.

The desktop app asks before quitting, closing its window, or reloading/navigating the native window while an event editor is open, even before its first edit. Cancel that native warning to keep the form, then save or cancel the event editor before retrying. Closing the editor after a successful save removes that extra warning. Browser-tab reload and programmatic Web route changes currently have no event-draft guard; save the event before leaving.

Dates and clock changes

All-day dates stay on their authored dates regardless of the device time zone. Internally the end is the following, excluded day; the form and event label show the inclusive last day. Timed events belong to the device-local day or days they overlap, and their row labels use the event's named time zone. A midnight ending does not add the next day. A week starts Sunday in the current Calendar.

A local time skipped by a clock change is refused. A repeated local time is also refused until you choose its UTC offset in UTC offsets for repeated times. For example, the New York fall clock change can repeat 01:30: -04:00 and -05:00 select different instants. An offset must match the named zone at that instant. No time is invented for an unknown event date/time.

Trash and restore

Move to trash keeps the saved event and its identity. Undo restores that deletion, and Show trash lists deleted events in the selected vault even when their dates are outside the visible period. Restore brings back the stored title, dates, description, references, and status; edit it afterward to make further changes. There is no permanent purge operation in this slice. Moving an event to trash discards unapplied form edits and preserves the last saved content.

CLI

The CLI uses the same validation, revision checks, and retry rules as the editor. Supply a UUID for the event and a different UUID for each distinct operation. Keep both IDs and the payload unchanged when retrying an uncertain response.

cat > /tmp/track-event-example.json <<'JSON'
{"title":"Review","all_day":true,"start":"2026-10-28","end":"2026-10-31","time_zone":"","description":"Read the source first","location":"","url":"","note_id":"","status":"confirmed","deleted":false}
JSON
track event save --id aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa --expect 0 --operation bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbbb < /tmp/track-event-example.json
track event list
track event get --id aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa

Use --expect 0 only for creation. For an edit, use the current revision returned by get/list, and a new operation UUID. deleted:true moves an existing event to trash with its other fields unchanged; deleted:false restores it using the latest revision. track event list --deleted includes trash. Timed JSON may provide local YYYY-MM-DDTHH:mm values with time_zone, or explicit RFC3339 values with a matching UTC offset.

Storage and limits

Events are authoritative, versioned files under calendar/events/ in the vault. Include that directory in vault backups and sync. Reindexing notes does not erase or recreate events, and no existing notes or tasks are migrated. A corrupt event file is reported as an error rather than silently omitted. Non-regular record files, including named pipes, are refused without waiting for another process to open them.

Static site export does not publish event files or event descriptions. The published calendar continues to show its dated-task snapshot. Events currently work in the live Web workspace and the desktop app that shares it. Actual native interactions require platform verification.

This slice handles single events. Recurring series, reminders, external calendar synchronization, invitations, and automatic research actions are not provided. A source URL and related note can prepare a manual research workflow without starting an external action.
