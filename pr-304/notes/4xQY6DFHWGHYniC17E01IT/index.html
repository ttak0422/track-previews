Markdown viewer

Markdown viewer

Read local Markdown files in track's reading view without adding them to a vault. The viewer uses the workspace's typography, theme, and reading settings, but the selected files remain a separate, read-only source. They are read in your browser's memory: track does not upload, import, or index them, and the viewer cannot edit them.

Open a file or folder

  1. Start the live Web workspace with track web and open the address it prints.
  2. Choose Markdown viewer in the navigation rail, or open /markdown on that workspace.
  3. Choose Open Markdown files for one or more .md or .markdown files, or Open folder for a directory containing Markdown and its local images.
  4. Use the file selector to switch between the selected Markdown files. The viewer prefers a README.md or README.markdown nearest the selected root; otherwise it opens the first Markdown file in sorted order.

Folder selection includes files in its subfolders and preserves their relative paths. Choose a folder when a README links to nested documentation or images. Picking individual Markdown files does not give the viewer access to the rest of their directory.

This viewer is available in the live workspace, not the published static help site. Source selection accepts local files and folders, not remote URLs.

Follow local links

Ordinary Markdown links can open another selected Markdown file. Heading links work both within the current file and across selected files:

[Setup on this page](#setup)
[Installation guide](docs/install.md)
[Install requirements](docs/install.md#requirements)
![Overview](images/overview.png)

For that example, select the containing folder with this layout:

project/
  README.md
  docs/
    install.md
  images/
    overview.png

The #setup link targets ## Setup in the current file; #requirements targets ## Requirements in docs/install.md. Relative paths are resolved from the Markdown file that contains the link. They can only reach files in your selection: a link cannot grant access to a neighboring folder, an unselected file, or a vault note. Choose a larger containing folder if the documents need shared files outside the folder you initially selected.

Local PNG, JPEG, GIF, and WebP images are displayed only when their files are included in the selected source. Remote images and rich embeds are not fetched automatically. An explicit click on an ordinary HTTP or HTTPS link opens that external destination normally; it does not load it as a viewer source.

What renders

  • Standard Markdown, GFM tables, read-only task lists, syntax-highlighted code, and math use the normal reading styles.
  • Raw HTML is not rendered. HTML cannot introduce scripts, frames, or remote resources.
  • Vault wiki links, includes, queries, and task-update controls are inactive. Their source remains plain text or code rather than resolving against your vault.
  • Diagram and data fences, including Mermaid and track query blocks, stay as inert code. The viewer does not execute code or activate the vault's diagram, chart, or dashboard features.

The viewer deliberately renders a smaller set than a trusted vault note. See Syntax for the normal note syntax and Embeds for features that apply to vault notes instead.

Refresh or close a source

The viewer reads a snapshot of the files you choose. After editing a file on disk, use Open Markdown files or Open folder again to read the updated contents. There is no automatic disk watching or write-back.

Normal navigation to a vault note and browser Back keep the selection during the current page session. A full page reload forgets the selection, so choose the files or folder again. The /markdown address alone cannot restore local files or share them with someone else.

Choose Close source to forget the current selection immediately. This does not delete or change any file on disk.

Limits and troubleshooting

  • Each Markdown file may be at most 2 MiB; each supported raster image may be at most 10 MiB. Reduce an oversized file before selecting it again.
  • Markdown must be valid UTF-8. If the viewer reports an encoding error, save a UTF-8 copy in your editor and select it again.
  • A selection may contain at most 5,000 files, including unsupported files in a selected folder. For a large repository, choose its documentation folder instead of the whole repository.
  • Each selected source can load at most 128 images totaling 32 MiB. If later images become unavailable, choose a smaller source.
  • If a folder contains no supported Markdown files, choose a folder containing .md or .markdown files instead.
  • If a local link or image is unavailable, check its relative path and make sure its target is in the selected source. The viewer cannot fall back to reading arbitrary disk paths or the vault.
  • SVG, HTML, PDFs, videos, and other rich embeds are not supported local images.
  • Folder selection depends on the browser. If it is unavailable, use Open Markdown files; use a browser with folder selection for nested documentation and images. File and folder choosers in the macOS app's embedded browser have not yet been verified.
