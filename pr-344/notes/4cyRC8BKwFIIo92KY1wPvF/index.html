Charts

Charts

track render turns a declarative View Spec (JSON) into a chart, reading data from the Canonical Data Model — plain JSONL files, one record per line, one kind per file. track never fetches data itself; external sources are converted into this model by separate track-fetch-* tools.

See also Diagrams and Embeds. For unavailable readings, start with Missing metric observations below.

Data: the Canonical Data Model

A data file is JSONL with one homogeneous kind per file. Every record carries a schema version.

KindRequired fieldsMeaning
eventtime, titleA point-in-time happening (news, post, milestone).
priceentity, time, open, high, low, closeOne OHLCV bar.
metricname, time, valueA named numeric sample, or an explicit missing observation with a reason.
entityid, nameA thing series refer to (ticker, index, sector).
annotationtime, textA label for narrative overlays.

The full field list (with optional fields and types) is printed by track render --help, derived from the typed structs so it never drifts. Example series.jsonl (a metric kind):

{"version":1,"name":"demo","time":"1","value":3}
{"version":1,"name":"demo","time":"2","value":7}
{"version":1,"name":"demo","time":"3","value":4}

kind is a real schema: rendering validates each record against it and fails with an error if a required field is missing or a numeric field is non-numeric, rather than drawing a partial chart. Extra fields beyond the schema are allowed, so a spec can still chart custom columns.

Canonical data files live in the vault's data/ directory (created by track init) — that is where track-fetch-* tools write their output. A spec references a file by path, so data may live anywhere a spec can reach.

Missing metric observations

A missing reading is different from an observed zero. Keep a dated record with "value": null and a nonblank missing_reason when a measurement is unavailable. Do not replace it with 0, copy the previous reading, or omit its date if the gap should be visible.

For example, save these synthetic readings as readings.jsonl:

{"version":1,"name":"news_sources","time":"2026-10-01","value":18}
{"version":1,"name":"news_sources","time":"2026-10-02","value":12}
{"version":1,"name":"news_sources","time":"2026-10-03","value":null,"missing_reason":"Collection unavailable"}
{"version":1,"name":"news_sources","time":"2026-10-04","value":3}
{"version":1,"name":"news_sources","time":"2026-10-05","value":0}

Save this View Spec alongside it as readings.json, then render it:

{
  "version": 2,
  "mark": "line",
  "title": "News sources (synthetic)",
  "data": { "kind": "metric", "source": "readings.jsonl" },
  "encoding": {
    "x": { "field": "time" },
    "y": [{ "field": "value", "title": "Source count" }],
    "detail": [{ "field": "missing_reason", "title": "Missing reason" }]
  }
}
track render --spec readings.json --out readings.html
track render --spec readings.json --out readings.svg --renderer svg

DateReadingExplanation

October 50The measurement completed and observed zero sources.

A source URL or vault note can travel with a reading using the existing encoding.href or encoding.note channel. Use encoding.detail for a reason, source label, or other extra columns; for a larger dashboard, the article table can keep all reasons and evidence visible. Tracking collection health and calculating the readings remain the producer's responsibility: track does not fetch data or infer why it is missing.

What charts and dashboards do with a gap

  • Line and area: break at the missing observation, without connecting across it or drawing zero. A date absent from the file cannot create a gap automatically; supply an explicit missing record.
  • Moving average: a window containing a missing observation is also missing. The average resumes once the complete trailing window has numeric readings.
  • Ranking: sort: "value" and sort: "-value" both place categories with no finite values after observed categories, then apply limit. A real zero still ranks numerically: in a descending ranking it comes before a negative value, while a missing value comes after both. Partially observed multi-series categories keep their existing sum of finite values; check completeness in the producer.
  • Gauge: an explicit null in the newest filtered input clears the needle and numeric reading. A later number, including zero, restores them. A gauge uses mark: "gauge" with "encoding": {"y": [{"field": "value"}]} and no x channel. Input order determines latest, so write observations in chronological order; track does not calculate freshness.
  • Dashboard import: a valid series containing only missing observations can still be selected by track metrics dashboard. It is an existing series with no readings yet, not an unknown series.

Fixing invalid metric records

Rendering stops with an error for malformed data instead of silently treating it as missing:

  • Keep name, time, and the value key on every record, including missing observations
  • Use JSON null, not the string "null", and provide a nonblank string missing_reason
  • Omit missing_reason when the value is numeric; a nonblank reason with a number is contradictory
  • Do not use NaN, infinity, an empty string, or arbitrary text as a number

These rules apply to metric.value; price OHLC fields still require numbers. Existing numeric metric records, including numeric strings, continue to work without migration. Older track versions may reject the new null form, so update readers before sharing datasets that use it.

View Spec: one chart

A View Spec names a data source, a mark (what to draw), and an encoding that maps record fields onto visual channels. It knows nothing about the renderer, so the same spec can be drawn by different backends.

{
  "version": 2,
  "mark": "line",
  "title": "Line",
  "data": {
    "kind": "metric",
    "records": [
      { "name": "demo", "time": "1", "value": 3 },
      { "name": "demo", "time": "2", "value": 7 },
      { "name": "demo", "time": "3", "value": 4 }
    ]
  },
  "encoding": {
    "x": { "field": "time" },
    "y": [ { "field": "value" } ]
  }
}
track render --spec chart.json --out chart.html

Rendered output:

Loading…

Key fields:

  • mark — line, bar, point, area, rect, candlestick, treemap, or gauge.
  • encoding.*.type — quantitative (default) or nominal (a category). Nominal on the right axis picks the form: a nominal-y bar is horizontal, a nominal-x point is a scatter (vs a bubble), and rect needs nominal x and y.
  • encoding.y[].axis — set "y2" to put a series on a secondary right-hand axis (two series on different scales).
  • encoding.y[].domain — optional [min,max] for a quantitative primary value axis. Shared-axis declarations must agree; bar/area ranges include zero; out-of-range data is a render error.
  • encoding.color — a nominal field that splits records into one colored series per value (on rect it is instead the quantitative heatmap cell value).
  • sort / limit — on the category-axis channel: order categories by label or value (ascending|descending|value|-value) and keep only the first N (top-N).
  • stack — on a bar's measure channel (y[0], or x for a horizontal bar): stack the series.
  • filter — {field, equals} shorthand, or {all: [{field, op, value}]} with op of eq|ne|lt|le|gt|ge for multi-field, range, and period filtering.
  • y[].mark — line|bar|area on a y channel draws that series in its own form: a combo chart (volume bars + an index line on y2). Dense category charts also zoom automatically: wheel/pinch always, plus a range slider past 30 categories.
  • y[].window — replace the series with its rolling mean over the trailing N records (a moving average); the first N-1 points stay empty.
  • overlays — reference geometry over the chart: {source, kind} (or {records, kind} with the events inline) draws events/annotations as vertical markers, {y, axis?, label?} a horizontal threshold line, {from, to, label?} a shaded period band, and {x, y, label} a callout bubble pointing at one data point. A marker overlay with display: "box" also draws each event as an always-visible annotation box hugging the plot (web reader only).

Embedding a chart in a note

Every image on this page is a View Spec asset rendered by track, not a hand-made picture. A .viewspec.json asset carries the spec and its data inline (data.records), so it is a complete, self-contained chart. Embed it like any image and track resolves it at build time; the published page draws it as an interactive ECharts chart:

![Line](assets/chart-line.viewspec.json)

Just drop the .viewspec.json file into the assets directory and reference it — no import step is required (track asset import only copies a file there for you). There is no separate data file to keep in sync and no CDN — the engine resolves the spec at build time and the site's bundled ECharts draws it. The charts below are each one embedded .viewspec.json.

Writing the spec inline

Prefer to keep the spec in the note itself? Fence a block with viewspec — the same way a mermaid fence embeds a diagram — and it renders as an interactive ECharts chart (hover tooltips, legend toggling) in both the web workspace and the published site. Inline data.records keeps the block self-contained; data.source reads a JSONL file from the vault's data/ directory. If the spec is invalid, the error and the source are shown at the block's position, so a typo never hides your text:

```viewspec
{
  "version": 2,
  "mark": "bar",
  "title": "Notes per week",
  "data": {
    "kind": "metric",
    "records": [
      { "name": "notes", "time": "W1", "value": 4 },
      { "name": "notes", "time": "W2", "value": 7 },
      { "name": "notes", "time": "W3", "value": 5 },
      { "name": "notes", "time": "W4", "value": 9 }
    ]
  },
  "encoding": {
    "x": { "field": "time", "type": "nominal", "title": "Week" },
    "y": [ { "field": "value", "title": "Notes" } ]
  }
}
```

Overlays — a vertical {records, kind} event marker, a dashed {y, label} threshold line, a shaded {from, to, label} period band, and a {x, y, label} callout bubble pointing at a data point, over any category-axis chart. The chart doubles as a scannable index of its evidence. The rail is drawn by the web reader (workspace and published site); the standalone HTML page, the composed article, and the SVG renderer keep the classic marker look.

Articles: prose + charts in one page

A spec with a blocks array composes Markdown prose, multiple charts, and filterable tables into a single HTML article — the "data + layout + rendering" unit for a data story.

The full notation (every field, all marks, examples) is always available with:

track render --help

Reusable metrics dashboards

Save a metrics-dashboard fence in an ordinary note. Reopening the note resolves its data bindings again; update the referenced JSONL with your collector, CLI, skill or AI without regenerating the screen. Existing note editing saves the title, panel order, layout and datasource bindings.

The fence uses the same Grafana classic JSON subset as track metrics dashboard. This is a Track chart dashboard, rendered locally with ECharts; it does not run Grafana or contact a Grafana server. The CLI importer remains a one-time conversion into View Specs; the fence retains the original selectors and resolves them on every display and refresh.

Minimal saved definition (place readings.jsonl in your vault's data/ directory):

```metrics-dashboard
{"title":"Service readings","panels":[{"title":"Readings","type":"timeseries","datasource":{"type":"track","uid":"readings.jsonl"},"targets":[{"expr":"news_sources"}],"fieldConfig":{"defaults":{"unit":"count"}}}]}
```

Use Period for all observations or a trailing day, week, month or year, measured from the request time. Refresh rereads the same bindings. Data-file changes and event-stream reconnections refresh the dashboard automatically. Click chart legend entries to select series; use the existing chart zoom controls for detail. Period and legend choices are session viewing controls; save a different JSON selector to change the dashboard definition. Panels resize with their container and stack on narrow screens. gridPos.x and gridPos.w use Grafana's 24-column grid; y orders panels. Fixed row heights, absolute vertical positioning, drag editing and gridPos.h are outside this subset.

Supported targets are a metric name with optional equality label matchers, such as demo_level{entity="technology"}. A live panel selects metric names from one file, optionally across entities and folded labels; mixed record units fail. The CLI importer requires one folded metric name. Put different metrics or units in separate panels. legendFormat supports {{entity}} and folded labels. Datasources use {"type":"track","uid":"<bare filename>"}; traversal and symlinks outside data/ fail. SQL, PromQL functions, dashboard variables and other panel types are not implemented. stat is displayed as a line chart. Limits are 48 panels and a 1 MiB request body. unit labels the axis without converting numbers; an absent or none panel unit uses the declared record unit; min, max and numeric threshold steps are supported. Other Grafana options/plugins are not interpreted; this is not a full Grafana importer.

Observation frequency, units and provenance

A panel reports latest observation time, data-file modification time, observations and explicit missing values. File modification is not source publication or collection time. Optional record fields unit, frequency, publication_frequency, scope, source, url, asof, available_at, fetched_at and revision remain visible in the series metadata or point tooltip. All optional fields, including nested provenance, source versions and publication/retrieval/ingestion evidence, are kept in expandable series metadata. A point's HTTP(S) url (or href) opens its source. The producer supplies these facts; Track does not infer them.

Date-only observations use UTC midnight as a reference for ordering and the rolling-period cutoff; this is not an intraday measurement. When every selected observation is date-only, axis labels stay date-only. Mixed timestamps are ordered as UTC instants. Original supplied timestamps, precision and timezone metadata remain available in series metadata and point details.

Use separate metric names for the original level, absolute difference and relative percentage change. A percentage level moving from 20% to 22% changes by 2 percentage points and 10% relative to its earlier level. Label these units separately; do not combine them on one scale. Financial computations belong in the finance adapter. Keep market-wide and sector observations explicitly distinguished in scope/entity; a market-wide series must not be presented as measured sector data. A weekly publication stays weekly even if the collector runs hourly. Track does not resample, invent intraday observations, fill gaps or evaluate stale-data alerts.

Display an existing Grafana dashboard

Use a separate grafana fence for an actual Grafana server:

```grafana
{"title":"Operations","url":"https://grafana.example.test/d/operations/service?from=now-7d&to=now"}
```

The reader must press Load Grafana from … before a frame is created. This admits only the shown origin for the mounted frame, not every dashboard or future visit. Disconnect Grafana removes the frame; Reconnect recreates it. Navigation away forgets admission. The external link remains available when offline, when a frame is blocked or when authentication requires a browser.

Only external HTTPS /d/<uid>/<slug> and /d-solo/<uid>/<slug> URLs are accepted (including a Grafana installation subpath). URL credentials, fragments, loopback hosts, Track's own origin and unknown query parameters are rejected. Accepted parameters are from, to, orgId, panelId, theme, kiosk, fullscreen, refresh, and var-*; keep secrets out of all URLs and note content. The frame has scripts and its own origin/storage, but no top navigation, popups, forms, downloads or native bridge access. The server is contacted directly by the reader's browser, without a Track proxy or credentials managed by Track. Trust the displayed server before loading it.

Grafana's viewer permissions, framing headers/CSP and browser/WebKit cookie restrictions still apply. Track cannot reliably inspect cross-origin frame success, so the external fallback stays visible. An existing signed-in session may work; interactive sign-in in the sandbox is not promised. No anonymous access, public sharing, authentication configuration or server is created for you. The native shell continues to block unrelated loopback frames and delegates explicit external links to the default browser. A real authenticated Grafana deployment needs its own end-to-end check.

See Grafana's sharing documentation and Grafana's configuration reference for server-controlled permissions and framing behavior.
