Web workspace

Web workspace

track web serves a local browser workspace for reading and navigating the vault. It is a thin frontend over the CLI: it renders note bodies, resolves [[...]] links into navigable, hover-previewable anchors, and draws the note graph.

Start, stop, and update the server

From Neovim, start the workspace with :Track web. Stop it with :Track webStop, then run :Track web again when you want to restart. Stopping does not restart automatically. Save any unsaved browser edits before stopping; the command does not save browser drafts.

Both commands accept an address, either as :Track webStop 127.0.0.1:8765 or :Track webStop --addr 127.0.0.1:8765. Without arguments, webStop targets the server started by this Neovim instance, using its launch address and environment even if you changed the plugin's web_addr setting afterward. With no active launcher job, it uses the current web_addr (default 127.0.0.1:8765) and current configuration. An explicit address selects that server.

The command uses the CLI's track web stop --addr ADDRESS and its PID record. It can also stop a managed server started outside Neovim when the address and cache configuration match. It reports an already stopped server without an error. If stopping fails, the launcher keeps its live job so you can retry; stopping a different address leaves that job alone. A missing PID record cannot identify an old listener, so the command does not kill a process merely because it uses the port.

Updating Track changes the installed binary, not an already running server. Stop the old server before opening the updated workspace. If Neovim itself still has the old plugin and bundled CLI loaded, exit and reopen Neovim after updating. From a shell, use track web stop --addr 127.0.0.1:8765, then start track web --addr 127.0.0.1:8765 with the updated CLI. See CLI.

Identify your macOS app build

In Track.app, choose Track > About Track to see the source commit, source state, and UTC build time of the running app. Choose Track > Copy Build Info to copy the full commit hash and build details when reporting a problem. The hash identifies the code used for that app, not the current checkout on disk. After updating the app, quit and reopen it to run the new build.

modified means the build included local source changes, so its commit is only the starting point, not an exact description of those changes. unknown means source metadata was not available, for example in a direct SwiftPM build or a source archive without Git history; it does not mean the latest version. Rebuild with make desktop-app from a Git checkout to include a commit. Older apps need rebuilding before they have these controls.

For a bundle built in the repository, this read-only command prints the same details without opening a window or starting the server:

"build/desktop/Track.app/Contents/MacOS/Track" --version

The reported identity belongs to that executable. To check an installed copy, use its executable path instead, or use About Track in the app you are running. These controls apply to the macOS app, not the separate track command-line executable or a browser server.

The experimental GPUI executable reports its own compile-time package version, full commit, tracked-source state and target in its diagnostics drawer and with track-gpui-poc --version. The command does not open a window, vault or server. Choose Track Native > Copy Build Info, or Copy Build Info in the native diagnostics drawer, to copy that same plain text. Only explicit activation writes the clipboard; opening the drawer does not. The copied text includes no note titles, vault paths, diagnostic errors or credentials. No keyboard shortcut is assigned; use Track Native → About Track Native for the native About dialog. modified covers tracked repository changes only; untracked inputs are not an attestation of source identity. unknown means Git metadata was unavailable. This is separate from the Track.app controls above.

Workspace navigation

The desktop sidebar is vertically centred in the full window. It stays below the tab strip as window size or text size changes. In a short window, scroll its navigation controls; Settings remains at the foot of the sidebar. At phone width or on a touch-only screen, the floating Track button replaces the sidebar.

What it offers

  • Rendered Markdown reading with GFM tables, task lists, and Mermaid diagrams.
  • Hover previews and persistent floating windows for linked notes and media.
  • A local link graph you can open per-note or full-screen.
  • Follow mode, so the web view tracks the note you are editing in Neovim.
  • A Markdown viewer for reading local files or a folder without importing them into a vault.
  • A configurable Home dashboard landing note, with recent-notes, journal, and pinned widgets.
  • Calendar events with single-event registration, time zones, related notes, and recoverable trash; alongside today's, tomorrow's, and this week's dated Tasks.
  • A metadata editor (the Meta dialog in the note actions menu): dedicated fields for the note's title, tags, description, cover image, and icon, plus a free-form block for Properties. Built-in fields get typed controls — the cover image can be uploaded straight from the browser into the vault assets — while props stays free-form YAML. The engine composes and validates the whole edit (the same rules as track meta --edit); the frontend never assembles YAML. Changing the title renames the note and rewrites its backlinks. The published static site has no editor.

Copy selected note lines

Select text in a vault note to open the copy popup in the live web workspace or Track.app. Copy range copies a path:start-end reference, Copy markdown copies the selected source lines, and Copy for Confluence copies formatted content for a rich-text editor. Source ranges cover whole Markdown blocks or list items, so selecting part of a paragraph copies its source lines.

Scrolling closes the popup rather than moving it with the text, including inside a floating note window. The text stays selected for ordinary keyboard copy. Select text again to reopen the popup. Published pages and the external Markdown viewer do not offer these source-line copy actions.

Background refreshes

The live web workspace and Track.app keep checking for note changes and storage recovery in the background. An unchanged storage check does not redraw an already writable note. Unchanged chart fences and published dashboard snapshots keep their chart state instead of restarting animations when the surrounding reader updates. Changed note or chart content still refreshes normally. Temporary read-only notes continue to retry after storage verification, without saving drafts. When several reads arrive together, previews wait briefly for a free read slot instead of failing immediately. Waiting and rendering share the same bounded deadline; a stalled or overloaded backend still reports an error. Editing again or closing the last view of a pending preview cancels that obsolete request. These read-only requests never save or replay your edits. If a preview refresh fails, a previously rendered preview of the same source stays visible with an error and Retry preview; task and diagram editing stay disabled until it recovers. If that source has never rendered successfully, Track shows escaped source instead. A failed refresh does not alternate a previously rendered note between formatted Markdown and source text.

When you are scrolled into a note, appearing or disappearing recovery notices preserve the current passage within that scrolling pane. At the top, notices remain visible without automatically scrolling past them. Refreshing prose in the same note no longer forces the whole Markdown view and all its diagrams to restart. Changing notes, switching display modes, following a heading, and enabled Follow navigation retain their normal navigation behavior.

Recovering from a note load error

In the live web workspace and Track.app, a failed background refresh leaves the last loaded note and any unsaved edits visible. An error explains that the displayed version may be stale. Select Retry to fetch the note again without reloading the workspace or discarding the draft. A successful refresh does not save your edits; use Save when ready. If the note changed on disk, the existing conflict protection still applies.

If the note has not loaded yet, Retry tries again and Close tab closes that failed tab. On the configured home note, which is not an ordinary tab, Go to workspace leaves the error view so you can use the navigation rail. Closing a tab does not repair a server error: other notes may fail too until the server recovers. Keep unsaved work in the editor or copy it somewhere safe before reloading or quitting.

Graph hover previews

In the full graph, rest the pointer on a node to preview its note. Move into the popup to read or follow a link; leaving the node and popup closes the preview after a short grace period. Hovering another node releases the previous preview. Dragging or resizing a graph preview changes its position or size without keeping it open. Panning, zooming, or resetting the graph also releases the current node preview.

Choose Pin preview to keep a window, including across page changes; choose Open as page or click a graph node to navigate to its note. Unpinning a graph preview restores its hover lifetime. Ordinary note-link previews keep their existing behavior: dragging or resizing one keeps it open until navigation. A link inside a graph preview opens an independent note-link preview; closing its source popup does not close that newer window.

Voice input

Open Voice input in the live workspace, then press the microphone to start Japanese recognition (ja-JP). Press it again to stop. Interim words remain provisional; confirmed text is editable, with the existing copy, clear, search, and journal actions.

The macOS app defaults to macOS speech, using Apple's built-in Speech framework on macOS 14 and later. Recognition also offers the existing Browser speech backend when Web Speech is available. Your explicit choice is remembered in this app; the web client continues to use Browser speech and keeps a separate preference. Upgrading changes the native default without requiring a provider key or changing other settings.

Built-in does not mean offline-only: macOS speech may send audio to Apple servers. Availability and offline operation depend on the language, device, system configuration, and network. Track checks Japanese support and current availability at start; Apple can also impose service limits. The browser backend follows the browser's speech service and may also process audio remotely. Track never switches services automatically after an error. Choose another available backend explicitly if needed.

Only starting voice input requests Speech Recognition and Microphone permission. If denied, allow Track under System Settings → Privacy & Security → Speech Recognition / Microphone, then try again. Restricted permissions need administrator help. No usable microphone, unavailable Japanese recognition, audio input changes, and service errors stop recognition and display an explanation.

macOS speech stops capturing after 55 seconds to stay below Apple's approximately one-minute task limit. Start again to continue. Stop releases the microphone immediately and allows up to three seconds for a final transcript; if none arrives, unconfirmed words are discarded with an error. Leaving the voice view, reloading, closing the app, or changing backend cancels the session and discards its provisional words. Only the active session can update the transcript.

Published site navigation

The published static site's sidebar omits New (recently created notes) and Voice input. Both remain available in the live web workspace and desktop app. Published sites keep sidebar search, browsing history, the note hierarchy, and the full graph for reading and navigation.

Retired agent requests

The built-in Agent requests panel and its explain, research, and update actions have been retired. Existing notes and .track/requests/*.json history stay in place. With a loopback track web server, GET /api/requests and GET /api/requests/<id> still read that history; add ?vault=<name> for a registered vault. These endpoints cannot send, retry, save, or apply requests. Interrupted updates remain recorded as they were and are never resumed automatically. Existing machine agents: settings are accepted but inactive; no credentials are removed or revoked.

Use the CLI from Codex or Claude for explicit note searches and edits. The Markdown viewer can display saved Markdown from an agent session without importing it into the vault.

Read Markdown outside the vault

Choose Markdown viewer in the navigation rail to open /markdown. Open Markdown files selects local .md or .markdown files; Open folder includes nested documents and their local images. Browser-selected files stay read-only in browser memory, with no upload, import, or indexing. Follow links within the selected source, then return to your vault without losing that selection during the page session. A full reload requires selecting the source again.

From Neovim, save the current Markdown file and run :Track markdown to open it directly. This starts or reuses a compatible loopback workspace and briefly transfers a read-only snapshot of the containing folder. No note is imported or indexed. Save and repeat the command to refresh.

See Markdown viewer for local links, rendering limits, refreshing disk edits, and browser support. This viewer is a live-workspace feature and is not included in the published static site.

Media embeds and diagrams

In a vault note, a Markdown image link on its own line becomes a rich block embed — YouTube players, Twitter/X posts, PDFs, image URLs, Open Graph link cards, and text-file attachments (including Mermaid diagrams). Fenced code blocks are syntax highlighted (with a copy button) and a mermaid fence renders inline. See Embeds for the full list and syntax, and Charts for .viewspec.json chart embeds.

Relationship to the static export

The static site produced by track export-site is the published counterpart of this workspace: rendered content only, with no editor, search index, or heatmap top page. It reuses the same Markdown and Mermaid rendering so a published note reads the way it does here, while Linking notes explains how cross-note links are resolved against the published set.

Static apps

A vault can keep a browser app at apps/<name>/index.html. A link to /apps/<name>/ or apps/<name>/ opens it as a top-level HTML page on a separate listener, not as a note embed. A link from a note in a registered vault opens that vault's app; a direct app URL defaults to the workspace launch vault. The app listener uses the workspace port plus one, and startup fails if that adjacent port is unavailable. See Static apps for setup, multi-vault behavior, trust boundaries, and publishing. For HTML displayed inside a note, see Embeds.

Searching from the workspace

The workspace search box runs the same unscoped search as the CLI as you type: title and #tag matches appear first, followed by full-text matches from note bodies in a separate Full text group. Body matches are ranked by relevance and include code-block and CJK matches. Use track search --scope body when you want body-only results from the CLI; the workspace already combines both scopes. See Searching notes for the query rules it shares.

Activity notifications in the macOS app

In Track.app, choose Track → Activity Notifications → Enable macOS Notifications… to request permission for standard macOS notifications. This is off by default. Opening the app or receiving an update never asks for permission. The menu shows the current permission state; Open macOS Notification Settings… lets you change an earlier denial in System Settings. Disable macOS Notifications returns activity to the in-app notification and clears Track's pending and delivered activity notices from this app session. The choice is remembered for this app.

External note activity uses the same system notification in the foreground and background, without a second in-app toast when macOS accepts it. Its title is Track and its message is generic: note titles, text, vault paths and note IDs are never included in the system notification, including its lock-screen preview. Click it while Track is running to open the affected note (the first note when several changes arrive together). The existing initial-load, own-save and once-per-note-per-day suppression still applies. Notification Center, Focus and your macOS alert settings control when accepted notices appear; acceptance does not guarantee an immediate banner.

If permission is denied or revoked, notifications are disabled, the bridge is unavailable, or macOS rejects a post, the clickable in-app activity notice remains available. Save and creation outcomes, including task-conflict errors, always stay in-app. Normal browser workspaces keep their existing in-app behavior; published static sites do not monitor live vault activity.

Track detects new activity only while its app and local server are running. Closing its last window quits the app; there is no background agent or push service. A notification left in Notification Center after quitting can reopen Track, but does not reopen its old note: note routes stay only in memory to avoid opening an ID in a different launch vault. A session can retain up to 1,000 activity routes; further activity uses the in-app fallback until the app restarts.

HTML/SVG attachments served by the live workspace run with a sandboxed, opaque origin, even when opened directly. Scripts may run, but attachments cannot access the parent workspace, its local storage or its native bridges. Use Static apps for separately hosted applications.

Find and navigation in the macOS app

Track.app uses Track's white t on a dark rounded square in Finder, the Dock, and the Cmd+Tab app switcher. This app icon stays the same when you change the workspace's light/dark theme. Build and open the .app bundle to see it; running the standalone executable is not an icon check.

In Track.app, Cmd+F opens a compact in-page Find panel below the tabs. Opening or closing it keeps the tab bar and reading viewport in place. Type a word or Japanese text from the rendered note: every match receives a soft highlight, and the current match uses the workspace's accent color. The counter shows the current match and total. Cmd+G or Enter moves to the next match; Shift+Cmd+G or Shift+Enter moves to the previous one, wrapping at either end and scrolling the current match into view. Escape or Done closes the panel and removes the highlights; clearing the query also removes them. Ordinary text selections and links remain intact.

Find is literal and case-insensitive, not a regular-expression search. It searches rendered text in the current reader, including text split by inline formatting and line breaks, and refreshes when you navigate or rendered content changes. Hidden text, editor drafts, embedded pages, images, and diagram canvases are excluded. The workspace search above searches across notes. On older WebKit versions without CSS Highlights (before Safari 17.2), Find retains its previous single-match selection behavior without the all-match counter.

Selecting a Contents heading moves within the current note without discarding edits or asking whether to leave. Moving away from an unchanged note also does not show an unsaved-edits warning. For edits to the note body, navigation that replaces the page (including Reload) still asks before discarding the draft. Cancel keeps the draft. Save first if you want to retain it; a failed save or a save still in progress does not count as saved. Uncommitted input from an input method is protected as well.

Window Close, Cmd+Q, and a macOS request to quit also check the current workspace. Unchanged or successfully saved notes and an empty tab strip close without an unsaved-edits warning. If a note has unsaved changes, choose Cancel to keep editing and Save before quitting, or Continue to discard them. Pending or failed saves and uncommitted input-method text remain protected. The app keeps the window open until its own local server has stopped.

The tab strip keeps the same height when no tabs are open, with the working-vault selector (when available) at the right edge. Opening the first tab or closing the last does not move the strip or add an empty tab to keyboard navigation.

In Track.app, Cmd+W (File → Close Tab) closes the current tab. Closing the last tab leaves the workspace open; press Cmd+Q (Quit Track) to exit the application. Unsaved note edits, pending saves, and input-method composition ask before closing a tab. Cancel keeps both the tab and its draft; unchanged and successfully saved notes close without a warning.

The mouse Back and Forward side buttons select the previous and next open tabs, including tabs in the overflow menu and Graph, Calendar, and Markdown viewer tabs. The ends wrap. Repeated presses follow the order at the start of the sequence even though the selected tab moves to the front. Clicking or opening/closing a tab starts a fresh order. Switching away from an unsaved note uses the same discard confirmation. These buttons switch tabs inside Track.app; the View → Back and View → Forward menu commands and trackpad history gestures retain their page navigation. Mouse software must send the standard side-button events (buttons 4 and 5), rather than remapping them to other shortcuts. Browser workspaces and published sites retain their existing controls.

For pages whose editing state Track cannot inspect, including static apps, voice input, focused embedded pages, and open dialogs, the app keeps its conservative warning. A failed or unresponsive state check also asks before discarding anything; it never treats a timeout as a successful save.

Reading keys in the macOS app

In Track.app, click ordinary text or an empty margin in a note's Preview view, or use normal keyboard focus navigation to reach the Note reading area. While that reading area has focus:

  • j scrolls down and k scrolls up, three lines at a time. Holding either key keeps scrolling.
  • Tab opens the next note tab; Shift+Tab opens the previous one. The ends wrap. Hidden note tabs in the overflow menu participate too; Graph, Calendar, and Markdown viewer tabs are skipped.
  • Escape releases the reading keys. The next Tab or Shift+Tab moves keyboard focus normally, so links, controls, and the navigation rail remain reachable. Click the reading text or return focus to the reading area to enable the keys again.

Closing workspace search with Escape or choosing a result returns focus to the note Preview so you can keep scrolling without another click. Closing the native in-page Find bar with Escape or Done also resumes reading after removing its match highlights. An input, editable control, or open dialog that still owns focus keeps it; dismissing search opened from a text field returns to that field instead. Choosing a result resumes reading. Edit and Split mode do not acquire reading focus.

The first Tab uses the current tab-strip order. Continuing with Tab or Shift+Tab follows that same order even though the selected tab moves to the front of the strip. Clicking, leaving and returning focus, opening/closing a tab, or navigating another way starts a fresh order. Holding Tab does not rapidly switch tabs. With fewer than two note tabs, Tab keeps its normal focus behavior.

These keys apply only to note Preview mode in the macOS app. Edit and Split mode, text fields, editable content, links, buttons, embedded pages, search, open menus, dialogs, and input-method composition keep their existing keys. Selected text and its copy controls keep normal keyboard behavior; selecting text does not move focus. The native Find field keeps its text input and focus navigation. Ordinary browser workspaces and published sites are unchanged. A configured home note can be scrolled, but does not become an open note tab just by using these keys.

If a preview still contains unsaved edits, switching notes uses the existing discard confirmation; Cancel keeps the draft and current tab. Save first to retain the edits. Key customization through a configuration file is not available yet.

Editing draw.io diagrams

In Preview or Split, select Edit draw.io diagram above a drawio diagram, then Open online editor. This opens the official editor at https://embed.diagrams.net. It requires internet access and passes the selected diagram's XML to third-party code from diagrams.net. Track does not send the rest of the note. Do not open confidential diagrams in the online editor unless you accept that boundary. Reading diagrams still uses the bundled local viewer.

The open editor uses about 90% of the window's width and height and follows window resizing. In short windows, scroll the dialog to reach all controls. Drag shapes, connection endpoints, and edge waypoints in the editor to refine an architecture figure. Select Apply to draft, or Save inside the online editor, to return the full XML to the note. Track switches to Split so you can inspect the source and preview, then select Track's Save to persist it. Apply alone does not save the note. A failed or conflicting Track Save keeps the draft; resolve the disk conflict before saving again.

Cancel, Close, or Escape closes the diagram editor. After the online editor has opened, Track asks before discarding the session, including when no change has been reported yet. Leaving the note, closing its tab, reloading, or quitting also protects unapplied diagram edits. Canceling a discard confirmation keeps the editor open. Apply or cancel before opening another diagram. Use the visible buttons when an iframe consumes a keyboard shortcut.

Only complete, unindented backtick drawio fences in the current note are editable. Attachments (including .drawio.svg and .drawio.png), included notes, query results, external Markdown files, and published pages stay read-only. Editing note text uses the existing source editor. If the preview belongs to an older draft, its editing buttons disappear until it catches up. If a draft changes during diagram editing, Apply is rejected; cancel and reopen the diagram. Disk updates do not replace a draft while its diagram editor is open.

The editor receives and returns the entire XML document, including compressed pages and layers. The inline viewer displays only the first page. Returned XML must be valid draw.io XML, no larger than 4 MiB of text, and cannot contain a line that would close its surrounding Markdown fence. Loading or Apply timeouts leave the draft unchanged; check connectivity, cancel, and reopen. The online editor is provided by diagrams.net and may change independently of Track. Its iframe cannot open popups, navigate Track, download files, or save directly to the vault. Diagram media and editor resources may use the network. Track's Apply/Save flow needs no new account or service.

Continuing after a partial failure

A malformed or temporarily unavailable note no longer prevents the initial workspace from opening. The files that can be read remain available, even before there is a cached index. Partial results are labelled; cached content is never presented as a verified complete snapshot. Critical root, configuration, or database failures still require recovery rather than silently using empty settings.

A note whose optional backlinks, properties, or hierarchy cannot be loaded keeps its readable body and explains the partial state. Editing is disabled when the index cannot safely support it. A failed refresh keeps the last loaded note and unsaved draft, with an explicit retry. A failed first preview shows escaped source instead of an endless loading indicator. Task and diagram actions stay disabled while the displayed preview belongs to an older body or note.

A failed graph, formula renderer, or chart stays local to that feature. Other prose and navigation remain usable; graph and math retries are explicit. Diagnostics are retained in logs without repeated popup cascades. If the interactive application bundle cannot load, first-paint content is kept and a reload action is offered. A failed save is still an error, and uncertain writes are never retried automatically. A missing file or sidecar does not become an empty editable document or a confirmed deletion. See CLI for explicit cleanup of intentional external deletions.

Slow or blocked storage at first launch

The workspace shell opens before configuration, title checks, or indexing finish. Its storage notice shows initializing, partial, or unavailable until the configuration and index are verified. Confirmed files can appear progressively even with an empty or blocked cache. A healthy registered vault can answer independently of a slow vault. The external Markdown viewer can receive saved snapshots while vault initialization is pending. Retry storage requests a new verification pass; it does not retry saves or discard drafts. A still-pending cache open keeps its admission slot, so clicking Retry cannot create an unlimited number of opens.

Reads have time and size budgets. An individual text read normally has two seconds and a 16 MiB limit; an HTTP read has a one-second response budget. Large or slow inputs can therefore remain unverified. The notice and partial-result fields distinguish this from a complete empty vault. When available, the last verified response is shown read-only and labelled as cached. Reading a snapshot never authorizes an overwrite, metadata update, or deletion. Display modes, Follow, and copy remain available during verification; metadata changes, deletion, and Save stay disabled. Routine background rechecking keeps the last completed storage health while it runs. A successful check with no content or health changes does not rewrite the index or refresh every open view. Initial verification, real read failures, and pending mutations still retain their recovery safeguards.

When verification finishes, temporary read-only notes refresh automatically with bounded attempts. Choose Retry note if one remains unavailable; this never retries a save. A late or cached read cannot replace your typed draft or roll a successful save back to an older snapshot. A configuration that changes the active vault requires a restart after preserving drafts.

A timed-out read worker is retired separately from the UI. If the operating system cannot reap it, its slot stays occupied; Track does not claim that a timeout cancels every filesystem syscall. Exhausted read capacity is reported explicitly. Storage writes and database cleanup may still need to finish before another write or verification attempt is safe.

Experimental GPUI workspace

An isolated GPUI workspace explores native rendering without replacing Track.app. From the repository root on macOS with Nix, a current Rust toolchain and Apple Command Line Tools:

./experiments/gpui/prepare.sh
cargo run --locked --release --manifest-path experiments/gpui/Cargo.toml -- \
  --vault /absolute/path/to/vault --track-bin /absolute/path/to/track \
  --server-port 19022

This starts an owned loopback Go server (the adjacent port is also required). The workspace is read-only. Search spans served vaults; note bodies use the raw source API, and local graphs follow the selected note's vault. Normal Quit waits for owned-server cleanup. Optional absolute --config and --cache paths isolate settings and derived caches. Ordinary engine indexing/sidecar maintenance can occur.

The native shell follows the existing sheet, floating navigation rail, title tabs, search overlay, reader and context-aside composition. Diagnostics are available separately; read failures and partial data remain visibly warned. Home shows a read-only activity heatmap. The aside shows cross-vault backlinks and vaults that could not be checked; selecting a backlink opens its source vault. CommonMark thematic rules render as native separators, including within quotes and list items. Rule punctuation is not reader text for Find; code containing the same punctuation remains code, and the source is unchanged. Use Find in the reader rail, or Cmd-F with reader focus, for literal body/table search. Enter and Shift-Enter move between matches; Escape clears highlights. Find reveals the active match’s first laid-out line, including matches late in wrapped paragraphs, code and table cells. A multiline match reveals its first line rather than the entire range; horizontal reveal is not provided. Ordinary fenced code with an explicit language shows a language caption and a Copy control on hover or focus. Copy puts the parsed code body on the clipboard without fences or labels. With reader focus, Option-C and Shift-Option-C cycle Copy controls; Enter or Space copies and Escape returns to the reader. Close Find before using these controls. This does not execute code; native clipboard/accessibility parity remains unverified.

Ordinary code fences have bounded lexical coloring for JavaScript/TypeScript aliases, Lua, JSON and Python (python, py, python3). Python coloring covers keywords, numbers, comments and single/triple-quoted strings. String prefixes and interpolations are not parsed: f-strings are approximated as ordinary strings, so nested quotes inside interpolations can be colored incorrectly. Contextual words such as match, case and type stay plain. This is a display hint, not a full Python parser. For example:

async def greeting(name):
    # Comments and quoted text keep separate styles.
    return f"Hello {name}"

Shell fences (bash, sh, shell) also have limited lexical hints for reserved words, comments and quoted strings. This is not shell grammar validation: substitutions and keyword positions are not parsed, double-quoted interpolation stays opaque, and an unquoted << sequence (including here-strings or shifts) leaves the rest plain. Unquoted parameter/command substitution openers also leave the rest plain. Nested quotes inside substitutions and ANSI-C strings may be colored incorrectly; newline handling is display-oriented rather than shell validation. Zsh is not included in this subset. Nothing is executed.

Unsupported languages and blocks above 64 KiB or 8192 token runs stay plain. Coloring never changes the code used by Find or Copy. Native contrast, selection, overflow and accessibility still need validation. Tab persistence, journal creation, rich formats, editing, live event refresh and native accessibility/IME parity are not complete. Basic Markdown, inline styling and simple tables render natively. Verified internal links navigate through the engine resolver; unsupported external links and rich content remain inert or literal. Graph settling runs off-thread; elastic dragging and preview parity remain incomplete.

Omit --server-port for the transitional CLI reader (portable Markdown, never an editable source). Pass a track notes JSON snapshot instead of vault options for metadata-only inspection. With no arguments, search a synthetic 10,000-note fixture. Keep exported snapshots private. No rendering-performance advantage is claimed. See experiments/gpui/PARITY.md and UI.md for verification gaps.

The native reader displays resolved titles for unaliased explicit-ID wiki links. Explicit labels and ordinary Markdown link labels are preserved. Unverified or unresolved targets retain their original text. This does not enable transclusion; native link hit regions and Find/heading interaction for substituted titles still need validation.

The native reader displays ordinary task-list check indicators and inline strikethrough. Indicators are read-only, not toggle controls; checked labels are not automatically struck. Rich task tables, custom states and date editing remain unsupported. Native alignment and accessibility validation are still pending.

In the native reader, explicit absolute HTTP(S) links can open in the default browser after a pointer click, including local HTTP destinations. Credential-bearing URLs and file/custom schemes stay inert; no automatic URL fetching or opening is performed. Browser navigation is separate from note navigation and is disabled during fixture editing or unavailable-reader states. Actual browser delivery, keyboard activation and accessibility are not yet validated.

The experimental native reader has session-only page history. Use the Back and Forward rail controls on Home, Graph or a note; unavailable directions are dimmed. With reader focus, use Cmd-[ for Back and Cmd-] for Forward. It remembers up to 100 accepted Home, Graph and note routes independently of tab cycling. It preserves the engine's order, omits the source journal, and opens results through normal guarded navigation; Back returns to the journal. It does not change Home's selected day or display zone.

Empty results, incomplete/cached results and unavailable reads are distinct. Use Retry after a failed or busy read. At most 100 notes are shown with an explicit count if more exist; there are no additional pages. This is not an anniversary, task/event view or NEW/read-status inference. It only reads existing data and never creates or edits a journal. Native GUI/IME/keyboard validation is pending.

Native reader j/k scrolling

Single-click a plain, noninteractive paragraph in the preview-only reader, then use lowercase j to scroll down or k to scroll up by three body lines. Key repeat is supported and movement stops at the edges. Escape releases this ownership; click eligible prose again to resume. Modified/uppercase keys keep their existing behavior. Links, code, tables, images, selection-style drag or multiple clicks do not acquire these keys. Editor/split, Find/search, composition, menus/dialogs, graph/preview/handoff and other input owners block this shortcut. The current plain text elements have no selectable-text/input-handler model; no global keyboard or IME handler is added. Native GUI/IME verification is pending.

Native View history controls

Use View → Back / Forward or ⌘[ / ⌘] in the active workspace, including Home, tag pages and full graph. Unavailable history directions are disabled. Existing dialogs, composition and save/recovery guards still apply; a dirty note uses the normal navigation decision. About and background windows do not route these commands to another workspace. Reader focus is not required. Reload is not part of this change. Native menu/keyboard verification remains pending.

Native recent notes

Choose Recent in the rail to reopen a successfully visited note, even after closing its tab. The popup keeps at most 100 distinct vault-qualified notes, newest first. Ordinary launches keep this list in memory only. A named working scope includes that vault and the launch vault; the default scope lists all recent visits. Close, Escape, or an outside click returns to the unchanged reading position. This list is separate from Back/Forward. Explicit disposable-fixture session persistence can restore this list after restart, including notes whose tabs were closed, without opening or fetching them. Startup remains on Home. Failed reads and background reloads do not add visits. Hover-to-open is not implemented.

Fixture schema 6 stores only exact vault-qualified note identities and bounded cached titles in the existing protected metadata file. Registered peers remain part of the session identity while temporarily unavailable; their availability still controls navigation. Actual registry changes disable persistence. Unknown vaults, duplicates or invalid fields disable persistence without replacing the evidence. The total 128 KiB snapshot limit still applies, so a full list of long labels may exceed it; the warning means persistence is unavailable, not that rows were silently dropped. This does not enable ordinary-profile persistence or editing, and queued metadata is not guaranteed durable on immediate or abrupt quit.

Native weekly tasks

On Home, expand Weekly tasks to read scheduled and due tasks from the current working vault. The default scope means the launch vault, not all registered vaults. Previous week, Next week, and This week reuse that snapshot; Refresh / Retry reads it again. Weeks run Sunday through Saturday using the device-local civil date, independently of the calendar-event display zone.

A task appears on both its scheduled and due dates, once when those dates are the same. Completed and cancelled tasks are excluded. Overdue appears only when the displayed week contains today and may repeat a task already shown on a day. Rows open their source note through normal guarded navigation; they cannot change a task or jump to a guessed line. This is not the full Calendar or an events view.

Loading, errors, and incomplete/cached snapshots are shown explicitly. Empty days mean no matching task in the received snapshot, not proof that the vault is empty. The existing reader accepts at most 4096 task rows; each displayed section shows at most 100 with an omission count, and long labels are shortened with an ellipsis. Unsupported task wire data produces an error rather than being silently discarded. The view adds no note, task, preference, or session writes. Native GUI validation for this addition is pending; ordinary editing remains gated.

Native local PDF inspector

On macOS, a standalone ![caption](assets/document.pdf) attachment offers Load in the reader's LOCAL PDF rail. Previous / Next changes one page at a time; the counter always describes the displayed image, including while another page loads. Close PDF releases the document. The authored Markdown stays unchanged.

This first slice lists at most eight local attachments and keeps one PDF active. It rejects encrypted, missing, malformed, or oversized documents. Limits are 8 MiB input, 256 pages, 1536 pixels per edge, and two million pixels per raster. A supervised helper has a five-second render deadline. Fixed-resolution images fit the rail and viewport; resizing does not rerender. PDF text selection, search, forms, links, downloads, remote PDFs, other embed syntax, and persistence are not supported. Rendering is not a security sandbox or a hard memory bound. Japanese/Latin page rendering, page navigation, encrypted-document rejection, and close/return behavior have been checked in an isolated macOS fixture. Cross-vault races, resize stress, and accessibility remain unverified; ordinary vault editing remains gated.

Enlarge displayed page opens the already-loaded PDF page over a dim backdrop. The label identifies its accepted page and total. Escape, Close, or clicking outside returns to the reader; clicking the page does not dismiss or advance it. This is a static snapshot, with no additional fetch or render, page navigation, PDF links, text selection, zoom, or pan. Resize preserves its aspect ratio and never upscales beyond the accepted raster, so enlargement may be less sharp than a fresh PDF render. Background reader commands are blocked while it is open; guarded application quit remains available. Source changes invalidate the view.

After loading a local PDF, Show PDF in reader displays the accepted page below that exact attachment's source label. Hide PDF in reader removes this extra region. Show/Hide preserves the current reading passage. The original visible label and source text remain, so Copy MD and source-text Find do not gain invisible matches; PDF text itself is not searchable. This differs from full replacement of the attachment notation in the web viewer.

The projected page uses a fixed 360-pixel-high, aspect-preserving region. Inspector page navigation updates both views atomically without changing this region's height; the old accepted page and counter stay visible while loading. No extra fetch, rendering, or image allocation is needed. Hide the projection before closing the PDF or loading a different attachment, including another occurrence of the same filename. Source changes invalidate it. Narrow layouts, bottom-clamp transitions and interrupted storage changes remain under validation.

Native query note navigation

In a rendered host-note query, Open note on a list row, board card, gallery card, or visible calendar row resolves that row through the engine and opens the result through normal note navigation. An explicit nonempty target takes precedence; only missing/empty targets use the title as a normal wiki lookup. Numeric labels are never converted to IDs, and a failed explicit lookup never falls back to its title or creates a note.

Loading and lookup errors remain visible in the original preview. Source, scope, registry, pagination, and snapshot changes cancel stale navigation. Resolved vault identity is preserved without a launch-vault fallback. Query text and note content are not changed. Included-note query rows, whole-card clicks, keyboard activation, modifiers/new tabs, and hover previews remain inert in this initial slice. List, board, gallery and Back navigation were checked in an isolated title-mode fixture; cross-vault, error races and IME still require native validation.

Calendar offers controls only for the first three rows per date, in supplied order. Day numbers, blank cells and +N counts do not navigate. Month changes invalidate pending row authority. Calendar native validation remains pending.

Inline query summaries (experimental native)

After loading the owned rendered-content snapshot, the Rendered content section offers Show/Hide for strictly matched standalone host track-query fences. One summary can be shown at a time. It retains the original visible query source and presents up to 100 rows, across all groups, in a fixed-height scrolling panel. Empty results are explicit; excess rows remain available in the rendered preview. This is a text-only summary, not the Web list/board/gallery layout or automatic query replacement. No extra evaluation or cover fetch occurs. Includes, additional source transformations and ambiguous mappings remain inspector-only.

Open note uses the same source-qualified resolver as the rendered preview. Hiding the summary or changing its source cancels pending navigation authority. Source Copy MD, Find and heading indices remain authored-source based; summary text is outside reader Find/selection. Normal vault write and session gates remain unchanged.

Open an included source note

Successful include headers in the rendered-content preview offer Open source note when their accepted note identity and vault are available. This opens the whole source note through normal guarded navigation; aliases, captions and excerpt line numbers are not destinations. Failed, incomplete, unsupported or stale include entries have no action. Changing the host, preview, working scope or vault registry invalidates old controls. Included body links and whole-card clicks remain inert, and no recursive expansion or note creation is added. This control does not promise a jump to the excerpt's heading or line.

Included wiki-link controls

The rendered preview offers explicit Open included link controls below accepted included prose. The original body links are not directly clickable. Up to 16 supported wiki or simple Markdown link occurrences per excerpt receive controls, in source order; aliases label controls but never select destinations. Plain wiki targets and authored heading/block fragments use the included note's vault, including an explicitly selected launch vault, without host-vault fallback. Successful navigation opens through the host's normal guarded history; errors keep the preview visible.

Other Markdown targets, local anchors, footnotes, code/query-generated links, external URLs, assets, hover, keyboard and modified-click behavior remain excluded. Existing query and excerpt controls share one bounded lookup worker. Source, excerpt revision, occurrence, preview, registry or scope changes invalidate pending navigation. No recursive expansion, note creation or ordinary-vault/session writes are added.

Wiki titles ending in a bare #, such as [[C#]] or [[C#|Language]], retain that character as part of the note title. Nonempty suffixes such as [[Note#Heading]] remain fragments.

Included Markdown note-link controls

The same explicit included-link controls also accept simple relative Markdown note targets such as [Design](Design.md), [Title](Title.MD) and [Café](Caf%C3%A9.md). A literal .md suffix is removed case-insensitively before strict percent decoding; an encoded suffix in Title%2Emd remains the literal note title Title.md. Labels do not select destinations. Lookup uses the included vault, never a fallback to the host.

This conservative subset rejects query strings, fragments, slash paths (including encoded slashes), schemes, absolute/local links, asset and application targets, other domain-like targets and malformed encodings. No browser or file opener is used. Wiki fragments retain their separate existing behavior. The combined wiki/Markdown limit remains 16 controls per excerpt, with the same source/occurrence guards and single lookup worker. Body links are still not directly clickable.

Native dedicated Calendar (read-only subset)

Choose Calendar in the rail. The month grid starts on Sunday and provides Previous month, Next month and Current month. Counts mean note activity in the current working vault only. They do not count tasks/events. Select any date, even one with zero activity, to inspect active notes, dated tasks and events using the existing day-details display-zone control. Incomplete counts are shown as unknown, not as proof of an empty day. Note actions use guarded source-vault navigation; the page never creates journals or changes tasks/events.

This tab supports Back/Forward, closing and guarded Reload. Month-wide note/task snippets, calendar editing and full planning UI are not included. The selected month/day are session-only. Explicit fixture persistence can retain the Calendar tab and history route in schema 7, but startup stays on Home and does not fetch Calendar. Schemas 1–6 still load; no startup migration or ordinary-profile writes are added. Isolated native checks covered zero-activity dates with tasks/events, vault scope, Search and task navigation, Back, Reload, month controls, and safe Home restart. Dirty/IME interactions and rapid-response races remain unverified natively.

Native Calendar month event previews

The Calendar grid reads one bounded engine-projected event range for the visible month, independently of note activity. Each date shows its event count, the first three event titles in engine order, a Cancelled: label when applicable, and +N events for additional records. Titles are shortened in cells; select the day for full metadata. Preview rows do not open links or edit events; the whole cell continues to select that date. Deleted records are excluded by the engine. Task and note previews are described below.

The month display-zone input starts at UTC and is session-only. Editing it hides old previews as unknown; choose Apply / retry month summaries for a new range. A selected day's existing details retain their own response zone until their separate Apply action or a new day selection. Loading, invalid zones, missing API, read failures and incomplete responses are unknown, never zero events. Zero is shown only for an accepted complete date bucket. Note-activity failure does not prevent event previews or day selection; its counts remain unknown.

The native adapter requires all dates in order, at most 42 inclusive days, maximum three previews per day, bounded identities/titles and at most 4096 source events. It shares the existing two-request permit with day/weekly work, never makes one request per month cell and does not compute event timezone membership locally. Month, zone revision, scope, registry, request, launch and storage changes retire prior results. No vault writes, new session fields or external calls are added. Isolated native QA verified host event counts, cancelled labels, overflow, zone-change invalidation and day details. Cold foreign-scope loading and switching back to the launch vault were verified after separating canonical reads from peer index startup. Real IME and native DST transitions remain unverified.

Native Calendar month tasks and notes

Each month cell now shows events, dated tasks and active notes as separate sections, each with up to three previews and its own +N count. Select the cell for the existing read-only day details; snippets and overflow counts do not open notes independently, and clicking a journal date does not auto-open or create a journal. Task previews include completed states and use the engine's scheduled/due membership (one entry when both dates match). Note previews follow authoritative activity dates and engine ordering, not a guessed creation date.

Task due bars use today returned by the engine in the selected display zone, not the selected cell or the computer's local date. Due today is a full bar; seven days away is half, fourteen or more is empty, and overdue is full in the warning color. Tasks without a due date have no bar. Completed tasks use the same text and bar treatment. A syntactically valid but impossible due date is preserved in the task record but does not draw a misleading bar. All labels are read-only, shortened to fit cells; the engine additionally bounds each preview label to 256 UTF-8 bytes. Day details remain the route to fuller information.

Choose Apply / retry month summaries after a display-zone edit or an unavailable index. The task/note summary only reads an already verified index: cold, partial, changed or failed index reads show unknown, not zero, and never silently retry. Event and task/note errors are independent. Initial loading runs note activity before the summary; Apply runs the event range before the summary, within the same shared two-request bound. Month, source, registry, storage and zone changes reject older results. Civil task/note date membership is not timezone-rebucketed; the zone supplies the due-bar's current date.

All sections deliberately use the selected working vault (empty scope means the launch vault), rather than reproducing inconsistent cross-vault filtering in the web Calendar. This does not change the web implementation. Month summaries, selection and zones are not persisted; ordinary-vault write and session gates remain unchanged. Isolated native validation covered dense month layout, independent overflow, scope switching, zone-edit invalidation, retry and day details. Interrupted requests, native deadline-boundary timing and real IME remain unverified; this does not establish full Calendar parity.

Returning to the selected Calendar day

Within one running workspace, returning to Calendar via Back or its tab remembers the selected day in the displayed month. It reads fresh day details after the initial month requests finish; previous responses and navigation tickets are not reused. New day selections take precedence. A changed vault/scope, server or storage identity, registry, or displayed month clears this memory. An unapplied zone edit postpones restoration. Nothing is saved across restart, and this does not look up, open or create a journal automatically.

Opening an existing Calendar journal

Choose Open existing daily journal in selected-day details, or Open existing monthly journal beside the month controls. These explicit read-only actions look for a journal with the exact YYYYMMDD or YYYYMM title in the selected vault. An ordinary note with the same title is not a journal. Missing, ambiguous or unavailable lookup results leave Calendar unchanged; missing means no match in the verified index, not proof that no file exists. No journal is created.

A successful lookup uses normal guarded note navigation. The subsequent note reads must still match the requested journal identity, kind, title and vault. If the journal changes after lookup, an explicit reader error is shown instead of a mismatched body; use Back to return to Calendar and retry. Back retains the qualified month/day selection within the running workspace and reads fresh results. This is an explicit-action subset, not automatic cell-to-journal navigation. Startup and Back never look up or open a journal automatically.

Read-only rich task lists

Accepted host-note task lists with doing ([/]), waiting ([?]), cancelled ([-]), priority, scheduled or due metadata appear as STATE / TASK / SCHED / DUE rows. Nested tasks keep their indentation; text styling, internal links, priority and ordinary text remain in the task cell. Dates and state come from the task metadata accepted with that exact note body. No extra request, checkbox mutation, task editing or date picker is added.

This first slice preserves source order: view-only sorting is not implemented. It admits only pure unordered task lists with one-line task paragraphs, complete source-line correspondence and at most 256 projected rows per document (nesting up to eight levels). Plain [ ] / [x] lists, completion-stamp-only lists, mixed or unknown-marker lists, multiline/multiple-paragraph items, ordered lists, unsupported cell content and missing/invalidated metadata retain ordinary source rendering. Included excerpts, snapshots and query output are not projected.

Rows keep the original reader block indices and block IDs. Find and links use the displayed table cells, not hidden source paragraphs; Copy MD still uses the unchanged authored body. Partial text selection in tables remains unsupported, as with existing native tables. Save-side metadata invalidation falls back to source rendering until a fresh accepted read. Native layout, Find/link geometry, clipboard and interruption validation for these rich rows is pending.

Rich-list admission additionally requires exact authored text and metadata correspondence. Only unique trailing standalone [#A], [sched:YYYY-MM-DD] and [due:YYYY-MM-DD] tokens are projected. Progress cookies ([3/5], [50%]), repeat/completion tokens, block IDs, code spans, ambiguous or duplicate tokens, and any mismatching item keep the entire list in its original reader form. This conservative fallback preserves progress and links rather than silently dropping notation not represented by the task listing metadata.

Host-context-dependent Markdown reference links (including collapsed and shortcut forms), footnotes and non-inline parser links also keep the whole list in its original reader form. Inline Markdown and wiki links remain eligible; the table never reparses a resolved host reference without its definition.

Local display-math snapshots

For an accepted ordinary note, the DISPLAY MATH section offers Render math for bounded, standalone $$…$$ blocks. Rendering is local and explicit. After it succeeds, choose Show math in reader to place the typeset image below the still-visible original expression; Hide math in reader removes the image. Hide before rendering another occurrence or closing it. The original source remains available to Find and Copy MD. Equal formulas at different positions are distinct occurrences.

This is a display-only snapshot subset, not inline math or automatic equation replacement. $…$, code, mixed paragraphs, ambiguous mappings and transformed reader models (including rich-task projections) retain their original display. Unsupported or invalid expressions retain source and show a rendering error. No equation link, file import, external service, command or document write is provided. One renderer job is allowed; source changes cancel and invalidate its output. Input is capped at 4096 bytes, PNG output at 2 MiB, image dimensions at 1536 per edge and two million pixels. Decoder allocation limits are not a hard process-memory sandbox. Font and formula support are limited to the bundled renderer. Native layout, source-selection and passage-retention QA is pending.

Native flowchart subset

Rendered preview can display mermaid fences containing flowchart TD, flowchart TB, flowchart LR (or graph with the same directions). Supported forms are ASCII node IDs, plain-text rectangles A[Label], decisions B{Ready}, A --> B, and A -->|yes| B. Newlines or semicolons separate statements. Node order and direction are preserved; isolated nodes, branches and joins remain visible. Cycles, other shapes, HTML, entities, Markdown styling, directives and ambiguous syntax retain source with an unsupported reason rather than a partial diagram.

The view has its own scroll area, with no pan/zoom or active links. Original source and Copy source remain available. Flowcharts share the eight-visual preview budget; limits are 16 KiB source, 64 nodes, 128 edges, and 256-byte labels. Extremely large measured layouts remain literal. Native visual verification is pending.

Rust and Nix code colors

Fenced rust / rs and nix blocks now have bounded, local lexical colors for keywords, numbers, comments and strings. Rust distinguishes lifetimes from closed character literals, shields nested block comments, and recognizes hash-delimited raw strings. Nix recognizes plain double-quoted and closed indented strings, including their literal escapes; code after a closed indented string is colored normally. These are lexical hints, not compiler validation or semantic tokens.

Nix interpolation is not evaluated or recursively colored. An unescaped ${ inside a string, an unfinished indented string, or path/URI-like syntax leaves that construct and the rest of the block plain rather than guessing nested boundaries. Embedded shell/Lua and other injections are not supported. Rust incomplete raw strings/comments remain opaque to the end. All source bytes, Find positions and Copy code output remain unchanged. Existing 64 KiB and 8192 token limits still fall back to plain display. Native visual QA is pending.

Read-only callouts

A blockquote beginning with a marker-only first line [!NOTE], [!TIP], [!IMPORTANT], [!WARNING] or [!CAUTION] displays a colored title and border. Kinds are case-insensitive. The marker line is omitted from the displayed body; inline formatting and links continue to use the visible body’s byte ranges. Original Markdown is unchanged for Copy MD. Find searches the visible body, not an invisible marker or the decorative title. Existing quoted-text selection limitations remain unchanged.

Ordinary quotes, unknown kinds, markers later in a quote, escaped/styled markers, code fences, custom titles and folding syntax keep their ordinary rendering. There is no collapse or edit action. Native visual/Find interaction QA is pending.

Copy selected Markdown lines

Select and release text inside one ordinary plain paragraph, then choose Copy selected Markdown lines beside the reader’s copy controls. This copies whole touched source lines, including their original line endings, rather than reconstructing Markdown from displayed text. Copy selection still copies only the selected plain text. The controls never write notes or save a selection.

The new operation requires exact correspondence to the accepted source snapshot. Styled/linked text, quotations/callouts, tables, transformed reader models, escapes/entities and soft-wrapped source paragraphs without exact correspondence are unavailable. Original CRLF line endings are preserved where correspondence is exact. Copy is refused while dragging, after source/route/scope/geometry changes, or when the source-line payload exceeds 256 KiB. Cross-paragraph dragging is limited to the adjacent-plain-paragraph conditions below; auto-scroll remains unsupported. Native pointer/clipboard verification is pending.

Selection across adjacent plain paragraphs

Dragging can now extend forward or backward across adjacent plain paragraphs that are fully visible and have exact source correspondence. The space between two measured paragraphs can bridge the selection. Copy selection joins their selected text with paragraph breaks; Copy selected Markdown lines uses the original touched lines, preserving interior blank lines and line endings.

There is no automatic scrolling. Crossing an unmeasured, offscreen or ineligible block cancels rather than guessing an endpoint. Headings, links/styles, quotes, tables and transformed or ambiguously mapped paragraphs are not bridgeable. When a multi-paragraph start is unavailable, existing single-paragraph selection remains available. Source, scope, document and geometry changes still invalidate selection. Source mapping is cached for one exact source/display snapshot only; a cache hit does not authorize clipboard access. Native drag/release sequencing and clipboard verification remain pending.
